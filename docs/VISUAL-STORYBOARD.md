# Recording storyboard

The existing `automatic-timeline.js` view now renders the stored scene sequence as a horizontal strip of compact selectable cards. It uses the existing `cheeseLouise:timeline:v1:<workspace>:<movie>` document, source records, scene IDs, revision/undo machinery and host notes. No new timeline store, backend, model, API or dependency is introduced. Existing manual talk-order data remains intact and is still the legacy import/fallback input; the competing legacy editor is no longer displayed beside the primary storyboard when that component is available.

On laptop screens the storyboard spans the recording workspace. Details open immediately below the cards, with the scene summary beside separate Nick and Jenny note panels. Next/Previous controls remain prominent; arrow keys and Home/End work in the card strip. Selected cards scroll into view after navigation and section changes, and selection reveals the hosts' notes above the persistent recording controls. Phones use large swipeable cards and stacked host notes. Editors, source material, exports and research/generation remain collapsible secondary tools.

The scene sequence is authoritative and can be reordered with Move earlier/later. Untimed scenes say Time unknown; empty summaries and missing observations remain incomplete. Plot outlines retain their order-needs-review label. No unsupported scene facts or times are generated. Source-supported trope candidates remain separate from verified or user-confirmed scene tropes. Hosts can link already-confirmed movie traits to the scene they actually observed, without modifying the movie's trait selections or any Bingo squares.

Funny observations and plot-hole notes are optional additions to the same scene objects. Edits autosave through the existing save path. Add, duplicate, merge, split, delete and undo remain available inside the scene editor. Merges retain former scene IDs as aliases for existing recording-marker references; marker movie/HQ times are never rewritten. Duplication and splitting do not duplicate those marker associations.

Recording segments, session storage, timestamps and Bingo imports/results use their existing components. Research remains strictly on demand, with its existing API-credit label; the redesign does not invoke paid research. Current selection and bookmarks persist in the existing document across recording sections and reloads. View-only editor disclosure and horizontal scroll state are held in memory.

Validation includes Node regressions for host-note separation, scene order and unknown timing, keyboard navigation, selection/bookmark recovery, observation merge/undo, confirmed-trope linking and marker association preservation. The assembled browser suite covers scene-card scrolling, selected-card visibility, scene navigation, both hosts' editable notes, return from the editing section, caption import and established Bingo/session features at 360, 768, 1024 and 1440 px. Tests use synthetic data, with external requests intercepted. No real notes or paid API calls are used. The existing intermittent Tools-menu focus assertion was retained; a rerun passed. A selected-card restoration failure found during testing was fixed by checking the selected card on each rendered strip.
